# 居家办公防沉迷健身插件（FitGate）设计方案

## 1. 项目背景与目标
针对居家办公久坐、刷社交媒体（如 X / twitter.com）时间过长的问题，本插件借鉴 `cat-gatekeeper` 的防沉迷与锁屏拦截机制，创新结合**本地 AI 计算机视觉人体姿态检测技术**：
- 当用户在 X 上的连续/累计使用时间达到设定阈值时，自动触发网页全屏锁定。
- 用户必须启动摄像头并在镜头前完成**指定数量的真实动作（第一阶段为标准深蹲 Squats）**。
- 只有 AI 真正检测到动作达标且完成指定次数后，系统才解除锁定，恢复网页正常浏览。
- 所有 AI 姿态推断与视频数据 100% 在本地浏览器内完成运算，严禁向任何云端上传视频或图像，保障隐私安全。

---

## 2. 系统总体架构与技术选型

### 2.1 架构分层
系统遵循 Chrome Extension Manifest V3 标准规范，包含以下 4 个核心构件：

```
+-------------------------------------------------------------+
|               Chrome Browser Runtime (MV3)                  |
+-------------------------------------------------------------+
|  1. Background Service Worker (集中计时、跨标签调度、状态持久化)    |
|       ^                        |                   ^        |
|       | 浏览心跳 / 状态同步      | 锁屏指令 / 解锁广播  | 解锁广播 |
|       v                        v                   |        |
|  2. Content Script (x.com 等)                      |        |
|     - Shadow DOM 隔离锁屏遮罩                       |        |
|     - 阻断滚动与点击交互                           |        |
|     - "去深蹲" 触发器 -----------------------------+        |
|                                                    v        |
|  3. 独立健身房页面 (workout.html) --------------------------+
|     - 摄像头获取 (一次授权)                                   |
|     - 本地 MoveNet Lightning AI 姿态检测模型                 |
|     - 骨骼夹角计算与深蹲状态机 (FSM)                          |
|     - 实时镜像、骨骼画布、角度仪表盘、次数计数、音频反馈       |
+-------------------------------------------------------------+
|  4. 控制台弹窗 (popup.html)                                  |
|     - 时长设置 (默认 20 分钟) / 动作次数 (默认 10 次)          |
|     - 今日累计健身次数与浏览时长统计                          |
|     - 受控域名管理 (内置 x.com, twitter.com，支持自定义)       |
+-------------------------------------------------------------+
```

### 2.2 技术栈选型
- **构建工具**：Vite 5+（极简配置，多 entry 打包，热重载与快速构建）。
- **AI 视觉引擎**：`@tensorflow/tfjs-core` + `@tensorflow/tfjs-backend-webgl` + `@tensorflow-models/pose-detection`（MoveNet.SinglePose.Lightning）。
- **运行环境**：Chrome Extension Manifest V3，所有脚本与模型产物全部离线本地打包。
- **音效系统**：Web Audio API 原生振荡器合成提示音，零外部资源依赖。

## 3. 核心机制详细设计

### 3.1 集中式精准计时与锁屏机制
1. **多标签页活跃监听**：
   - 监听 `chrome.tabs.onActivated` 与 `chrome.windows.onFocusChanged`。
   - `content.js` 监听 `document.visibilityState` 与用户活动（每 1 秒心跳检测）。
   - 只有用户激活并聚焦在受控网站时，秒数才递增并写入 `chrome.storage.local`。
2. **锁屏判定与注入**：
   - 当会话秒数达到 `usageLimit * 60` 时，Background 将该域名标记为 `locked: true`，并向所有匹配标签页下发 `LOCK_PAGE` 消息。
   - `content.js` 在页面挂载 `div#fitgate-host`，使用 Closed Shadow DOM 注入锁屏界面，设置 `position: fixed; inset: 0; z-index: 2147483647;`。
   - 监听并拦截页面键盘快捷键与滚轮事件，阻止滚动。
   - 注入 `MutationObserver`，若用户通过开发者工具移除宿主 DOM，立即瞬间重新挂载。

### 3.2 AI 视觉深蹲动作检测状态机 (Squat FSM)
1. **关键骨骼点识别**：
   - 提取人体 17 个关键点中的：双肩 (5, 6)、双髋 (11, 12)、双膝 (13, 14)、双踝 (15, 16)。
   - 自动选取画面中置信度更高的一侧（或正面双侧均值）作为主测算面。
2. **关节夹角计算**：
   - 向量 $\vec{A} = \text{Hip} - \text{Knee}$，向量 $\vec{B} = \text{Ankle} - \text{Knee}$。
   - 夹角 $\theta = \arccos\left(\frac{\vec{A} \cdot \vec{B}}{|\vec{A}| |\vec{B}|}\right) \times \frac{180}{\pi}$。
3. **状态机转换规则**：
   - **`WAITING`**：未检测到完整下半身，屏幕提示“请后退一步，确保拍到双腿”。
   - **`STANDING`（站立准备）**：膝关节夹角 $\theta > 160^\circ$ 且保持 $\ge 0.3$ 秒。
   - **`SQUATTING`（下蹲过程）**：$\theta$ 由 $160^\circ$ 下降至 $140^\circ$ 以下，UI 动态显示下压进度。
   - **`BOTTOM`（深蹲达标）**：$\theta \le 100^\circ$（触底达标），播放清脆“叮”音效，线条高亮变绿。
   - **`RISING`（起立归位）**：身体回升并恢复至 $\theta > 160^\circ$。
   - **结算动作**：满足单次动作物理耗时 $\ge 0.8$ 秒（防高频抖动刷分），有效次数 $+1$，重置为 `STANDING`。若未达底（如半蹲 $\theta = 120^\circ$ 即站起）则判定无效动作，不计次数。

### 3.3 达标解锁通信与无缝切换
1. 用户在 `workout.html` 达到目标次数（例如 10 次）：
   - 播放通关音效与撒花动效。
   - 向 Background 发送 `WORKOUT_COMPLETED` 消息。
2. Background 收到后：
   - 重置当前会话计时为 0，解除 `locked` 状态。
   - 记录今日已完成健身次数（累加到统计中）。
   - 向所有受控标签页广播 `UNLOCK_PAGE` 消息，Shadow DOM 锁屏淡出并销毁。
3. `workout.html` 延迟 1.5 秒自动调用 `chrome.tabs.remove` 关闭自身，用户焦点自动切回已解锁的 X 页面。

## 4. 异常处理与边界设计
- **无摄像头或拒绝授权**：`workout.html` 友好提示“未检测到摄像头或权限受限”，提供“重新检查权限”引导按钮，不产生白屏崩溃。
- **光线不足 / 遮挡**：当关键点置信度持续低于阈值时，屏幕提示“光线偏暗或身体被遮挡，请调整姿势”。
- **多窗口 / 多标签页**：后台集中控制计时与解锁状态，一个标签页解锁，其他已锁定的 X 标签页同步解锁。
- **防作弊机制**：物理耗时检查、必须达到 $\le 100^\circ$ 深度、起立必须站直 $> 160^\circ$。

## 5. 项目工程化与验证方案
- 单元与集成逻辑验证：状态机夹角计算、时间累加算法、消息传递逻辑。
- 编译检查：Vite 打包编译必须零报错、产出静态资源完全包含在 `dist/`。
- 真机加载验证：在 Chrome 中以“加载已解压的扩展程序”导入 `dist/`，进行真实视频流与深蹲测试。
